# Как устроена CRM

В CRM есть строительные объекты и назначенные по ним задачи. Руководитель создаёт объекты, ставит задачи и выбирает исполнителя. Сотрудник видит только свои задачи и те стройки, на которых у него есть поручения.

Сотрудник берёт задачу в работу и передаёт результат на проверку. Руководитель принимает работу или возвращает её с обязательным объяснением. После исправления сотрудник снова отправляет результат. Каждый шаг записывается: кто выполнил действие, когда и с каким комментарием.

Ограничения работают в самой базе данных. Даже если сотрудник обратится к базе без нашего интерфейса, он не сможет увидеть чужую задачу, назначить себе роль руководителя, принять свою работу за руководителя или переписать историю. Новые пользователи не могут зарегистрироваться самостоятельно — доступ выдаёт администратор.

Данные сохраняются для всей команды и доступны с разных устройств. Если два человека одновременно меняют одну запись, система не позволяет старой форме затереть свежие изменения: она сообщает о конфликте и загружает новые данные.

Удалённые задачи исчезают из рабочего списка, но их история сохраняется для проверки спорных ситуаций. Секретный административный ключ не выдаётся браузеру; сотрудники входят под собственными аккаунтами. Для сдачи подготовлены один постановщик, два исполнителя и несколько задач в разных состояниях.
